# SQLite 缓存机制

## 数据库位置

缓存数据库位于：

```text
%LocalAppData%\FileGroupy\Cache\scan-cache.db
```

缓存仅属于当前 Windows 用户。程序不会将缓存写入被扫描的目录、可移动磁盘或 MTP/PTP 设备。

## 职责划分

`ScanCacheDbContext` 及其实体类负责描述数据库结构，并用于结构初始化、缓存读取和缓存失效。

`SqliteScanCacheStore` 是扫描器与设备服务使用的统一缓存入口。它使用 EF Core 执行结构化读取和失效操作；针对大量扫描文件记录，使用参数化的 `Microsoft.Data.Sqlite` 命令在单一事务中批量写入，避免 EF 变更跟踪造成额外开销。

## 数据表

| 数据表 | 用途 | 主键 |
| --- | --- | --- |
| `scan_cache` | 一次扫描快照的元数据和统计信息 | `cache_key` |
| `scan_files` | 属于某次扫描快照的文件索引 | `cache_key`, `full_path` |
| `image_validation` | 栅格图像有效性校验结果 | 来源、路径、大小、修改时间 |

`cache_key` 由 `source_kind`、`source_id` 和 `root_path` 组成。这样本地磁盘路径与 MTP/PTP 虚拟路径不会发生缓存碰撞。

## 读取与写入流程

1. 扫描器按来源类型、来源标识、扫描根路径和 TTL 查询缓存。
2. 若缓存仍有效，EF Core 连同关联文件索引一起读取扫描快照。
3. 若缓存缺失或已经过期，执行真实扫描。
4. 真实扫描完成后，在一个 SQLite 事务中删除旧文件索引、更新扫描元数据、批量写入新文件索引。
5. 缓存读写采用 fail-open 策略。缓存数据库异常时，调用方继续使用真实扫描结果或重新执行图像校验。

## TTL 策略

| 来源 | 扫描缓存 TTL | 图像校验缓存 TTL |
| --- | --- | --- |
| 本地磁盘或可移动磁盘 | 10 分钟 | 24 小时 |
| MTP/PTP 设备 | 1 小时 | 1 小时 |

本地目录的子文件变化不能只通过根目录修改时间可靠判断。因此本地缓存设置为较短 TTL，在性能与结果新鲜度之间取平衡。

## 无效图像缓存

图像校验记录由以下字段唯一确定：

- 来源类型。
- 来源标识。
- 完整路径。
- 文件大小。
- 最后修改时间。

文件大小或修改时间变化后，原记录不会命中，程序会重新校验。

SVG 是矢量图像，不交给 WPF 位图解码器，因此不会被判定为无效图像。

MTP/PTP 图像按设备单会话顺序验证，避免对同一设备并发连接或下载，降低协议断连风险。

## 缓存失效

MTP/PTP 设备上的复制、移动或删除成功后，程序会按设备 ID 删除以下缓存：

- 扫描元数据。
- 文件索引。
- 图像校验结果。

本地与可移动磁盘不使用长期强制失效机制，而是等待短 TTL 到期后重新真实扫描。

## 删除找回事务日志

本地文件软删除不会直接调用永久删除。SQLite 只保存快照、原始路径、块清单、对象引用与事务状态；文件内容存放于：

```text
%LocalAppData%\FileGroupy\Recovery\objects\<HashPrefix>\<BLAKE3 Hash>.zst|.raw
```

对象库采用以下策略：

- FastCDC 内容定义分块，目标块 1 MiB，范围 256 KiB–4 MiB；单次最多读取 32 MiB，内存不会随文件大小增长。
- BLAKE3 作为块内容地址，相同块只保存一次。
- Zstandard level 3 压缩可压缩块；压缩后未节省至少 5% 时保存原始块。
- JPEG、PNG、视频、压缩包、Office Open XML、PDF 等已压缩格式直接原样保存。
- `recovery_objects.ref_count` 与 `recovery_item_chunks` 保证共享对象只在最后一个引用释放后删除。
- 恢复时按有序块清单流式解压/拼接，并校验最终文件大小。

旧版快照仍按原 `recovery_path` 恢复，新快照使用 `object://<ItemId>` 清单，两者可并存。

删除流程使用两阶段状态：

1. 先写入 `Pending` 快照与计划文件明细。
2. 文件分块写入对象库并提交清单后删除源文件，再更新该明细的 `is_moved`。
3. 所有成功转移的文件写入完成后，将快照标记为 `Completed`，此时才会在“删除找回”窗口显示。

应用启动时会修复 `Pending` 快照：对象清单或旧版恢复文件会重建至原始位置；全部回滚成功时删除未完成快照。启动维护还会校正引用计数，并删除未被 SQLite 引用的临时/孤儿对象。

恢复库中没有 SQLite 快照引用的空目录会被删除；非空目录会移动到：

```text
%LocalAppData%\FileGroupy\Recovery\Orphans\
```

隔离操作不会删除文件，便于后续人工核查。
